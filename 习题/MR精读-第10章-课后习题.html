题目 1点击展开解答 ▾

本章把规划问题放在 configuration space / state space 中讨论。按事实底座：

  • path planning 是纯几何问题，目标是找一条几何路径

\[

q(s),\quad s\in[0,1],

\]

满足

\[

q(0)=q_{\text{start}},\qquad q(1)=q_{\text{goal}},

\]

并且避开 \(C_{\text{obs}}\)，即

\[

q(s)\in C_{\text{free}},\quad \forall s\in[0,1].

\]

它不考虑 dynamics、duration、control constraints。

  • motion planning 则更一般。给定

\[

x(0)=x_{\text{start}},\qquad x_{\text{goal}},

\]

要找时间 \(T\) 和控制输入

\[

u:[0,T]\to U,

\]

使得

\[

\dot x=f(x,u),

\]

且

\[

x(T)=x_{\text{goal}},\qquad q(x(t))\in C_{\text{free}},\quad \forall t\in[0,T].

\]

因此 motion planning 不仅要回答“走哪条几何路径”，还要回答“用多长时间、施加什么控制、是否满足动力学”。

为什么 path planning 是 motion planning 的子问题？因为本章明确假设：path planner 返回的几何路径 \(q(s), s\in[0,1]\) 应能被 time scaled 成满足动力学/约束的 feasible trajectory。也就是说，若先忽略 dynamics、duration 和 control constraints，只求一条无碰撞几何路径，那么在第 9 章的时间缩放结论可用时，这条路径可以进一步被赋予时间参数，成为轨迹 \(x(t)\) 或 \(q(t)\)。所以 path planning 是 motion planning 中剥离了时间、动力学和控制后的几何子问题。

题目 2点击展开解答 ▾

A* 中，每个节点的估计总成本定义为

\[

\text{est\_total\_cost}[node]

=

\text{past\_cost}[node]

+

\text{heuristic\_cost\_to\_go}(node).

\]

其中：

  • past_cost[node] 是从 start 到该节点已经付出的实际成本；
  • heuristic_cost_to_go(node) 是从该节点到 goal 的估计剩余成本。

A* 每次从 OPEN 中取出 est_total_cost 最小的节点 current，加入 CLOSED。若 current 在 goal set，则返回路径；否则扩展未在 CLOSED 中的邻居 nbr。对邻居更新时计算

\[

\text{tentative\_past\_cost}

=

\text{past\_cost}[current]

+

\text{cost}[current,nbr].

\]

只有当

\[

\text{tentative\_past\_cost}

<

\text{past\_cost}[nbr]

\]

时，才更新

\[

\text{past\_cost}[nbr]=\text{tentative\_past\_cost},

\]

并设置

\[

\text{parent}[nbr]=current,

\]

然后按

\[

\text{est\_total\_cost}[nbr]

=

\text{past\_cost}[nbr]

+

\text{heuristic\_cost\_to\_go}(nbr)

\]

把 nbr 插入或移动到 OPEN。若 OPEN 为空则 FAILURE。

heuristic_cost_to_go 必须 optimistic，也就是必须低估从当前节点到 goal 的真实剩余成本。原因是：A* 只有在启发式从不高估真实剩余成本时，才能保证返回 minimum-cost path。若启发式高估，例如乘以 \(\eta>1\)，搜索会更快偏向 goal，但不再保证最优。

Dijkstra 与 breadth-first search 的关系如下：

  • Dijkstra 是 heuristic 恒为零的 A*：

\[

\text{heuristic\_cost\_to\_go}(node)=0.

\]

此时

\[

\text{est\_total\_cost}[node]=\text{past\_cost}[node],

\]

所以 A* 退化为按已走成本扩展。

  • 若所有边 cost 相同，Dijkstra 进一步退化为 breadth-first search。因为此时“已走成本最小”等价于“层数最少”，搜索按层扩展。

因此，A 的最优性依赖 optimistic heuristic；Dijkstra 和 BFS 都是 A 在特定启发式和边权条件下的特例。

题目 4点击展开解答 ▾

球近似距离公式为

\[

d(q,B)=\min_{i,j}\|r_i(q)-b_j\|-R_i-B_j.

\]

其中：

  • \(q\) 是机器人配置；
  • \(B\) 表示障碍；
  • \(r_i(q)\) 是机器人第 \(i\) 个近似球的球心位置，它依赖配置 \(q\)；
  • \(b_j\) 是障碍第 \(j\) 个近似球的球心位置；
  • \(R_i\) 是机器人第 \(i\) 个近似球的半径；
  • \(B_j\) 是障碍第 \(j\) 个近似球的半径；
  • \(\|r_i(q)-b_j\|\) 是两个球心之间的欧氏距离；
  • 减去 \(R_i+B_j\) 后，得到两个球面之间的净距离；
  • 对所有 \(i,j\) 取最小值，得到机器人球近似与障碍球近似之间的最小净距离。

若 \(d(q,B)>0\)，表示球近似下无碰撞；若 \(d(q,B)\le 0\)，表示球近似下接触或穿透。

球近似是保守的，因为球必须覆盖物体所有点。只有 grown bodies 无碰撞时，才能保证实际几何 collision-free。也就是说，球近似可能把实际物体包得更大，因此它可能报告“碰撞”而实际并未碰撞，但不会在实际碰撞时报告“无碰撞”。所以它是保守的碰撞检测近似。

Workspace potential 中，机器人控制点为

\[

f_i(q)\in\mathbb R^3,

\]

障碍边界点为

\[

c_j\in\mathbb R^3.

\]

Jacobian 满足

\[

\dot f_i=J_i(q)\dot q,

\]

其中

\[

J_i(q)\in\mathbb R^{3\times n}.

\]

若任务空间中的虚拟力为 \(F'_{ij}(q)\)，则对应的广义力为

\[

F_{ij}(q)=J_i^T(q)F'_{ij}(q).

\]

这是因为虚功原理要求任务空间力与广义力在广义位移上做功一致：

\[

\delta f_i=J_i(q)\delta q,

\]

因此

\[

(F'_{ij})^T\delta f_i

=

(F'_{ij})^T J_i(q)\delta q

=

\bigl(J_i^T(q)F'_{ij}\bigr)^T\delta q.

\]

所以广义力为

\[

F_{ij}(q)=J_i^T(q)F'_{ij}(q).

\]

题目 5点击展开解答 ▾

下面给出一个可运行 Python 代码，用于计算 \(k=100\) 时不同维数 \(n\) 的网格节点数：

k = 100
for n in [3, 5, 7]:
    nodes = k ** n
    print(f"n={n}, k={k}, nodes={nodes:,}")

预期输出为：

n=3, k=100, nodes=1,000,000
n=5, k=100, nodes=10,000,000,000
n=7, k=100, nodes=100,000,000,000,000

也就是：

  • \(n=3\)：1 million；
  • \(n=5\)：10 billion；
  • \(n=7\)：100 trillion。

这与本章给出的数值一致：\(k=100\) 时，\(n=3\) 为 1 million 网格节点，\(n=5\) 为 10 billion，\(n=7\) 为 100 trillion。

Grid 方法把 C-space 离散成

\[

k^n

\]

个网格点。固定分辨率下，存储与搜索时间随维度指数增长。即使每个维度只取 100 个格子，三维时是 100 万，五维时是 100 亿，七维时是 100 万亿。对于高自由度机械臂，C-space 维数 \(n\) 往往远大于 3，因此直接 grid 化会迅速变得不可接受。这就是 grid 方法的维数灾难。

Sampling methods，例如 RRT、bidirectional RRT、RRT* 和 PRM，通过采样、最近邻和 local planner 构建树或图，而不是显式枚举整个 \(C_{\text{free}}\)。它们通常具有 probabilistically complete 性质：随着采样增加，找到解的概率趋于 1。因此它们能缓解维数灾难，尤其适合高自由度系统。

但 sampling methods 通常给出的是 satisficing 解，而不是 optimal 解。也就是说，它们通常先找到一条可行路径，而不保证最短或最优。RRT* 是例外之一，它随规划时间增加使解趋于最优，但这需要额外计算。PRM 则构建 multiple-query roadmap，适合多次查询，但同样通常不以保证最优为首要目标。

因此，grid 方法在低维、需要 resolution-complete 最短路径时仍有价值；高维时则更常用 sampling methods，并接受 satisficing 解或使用 RRT* 逐步改进。
